## Why this matters

Tonal Foundry exports generated Swatch values as design tokens, but the seven
tests do not freeze those values. The CLI test computes its expected result by
calling the same `buildScale` implementation as the CLI, so shared numerical
regressions still pass. Independent literals must exist before Plan 005 changes
the Lab white point used for weight assignment.

## Current state

- `src/engine/__tests__/cli-scale.test.ts:26-42` defines `buildExpected` by
  calling production `buildScale` and mapping its result.
- `src/engine/__tests__/scale.test.ts:8-48` checks counts, flags, and output
  syntax, but no exact weights, colors, or metrics.
- `src/engine/__tests__/palette.test.ts:20-27` checks only Scale and Swatch
  counts.
- Test style uses Vitest `describe`, `it`, and `expect`, single quotes, two-space
  indentation, and no semicolons. Match `src/engine/__tests__/scale.test.ts`.
- The stable weight vocabulary is the ordered 23-item `weights` export in
  `src/engine/constants.ts`. Tests should use that production constant only for
  the declared contract comparison, never to generate expected colors or
  metrics.

Current coupled expectation:

## Steps

### Step 1: Create independent literal fixtures

Create `scale-goldens.ts` with checked-in literal expectations for:

1. the existing single-key primary Scale (`#3366ff`);
2. one existing multi-key Scale from `seedPalette`;
3. one Display P3 destination case.

For each case, record the exact ordered 23 weight labels and a small set of
representative Swatches: both locked endpoints, the authored Key position, and
at least one generated neighbor. Record destination strings and hex exactly;
record floating metrics as numeric literals checked with explicit tolerances.
Do not call `buildScale`, `buildPalette`, Color.js, or another production helper
from the fixture module.

Use the committed Prism OKLCH rows in `app/globals.css` as the approved prior
artifact where they apply. A value captured only from the current program is a
reviewed regression baseline, not an independent correctness oracle. In all
cases the committed fixture must be inert data and state its provenance.

**Verify**: `rg "buildScale|buildPalette|toColor|new Color|from.+constants" src/engine/__tests__/fixtures/scale-goldens.ts`
→ no matches.

### Step 2: Strengthen engine tests

Update `scale.test.ts` to compare the generated Scale against the literal
weight sequence and representative Swatches. Use `toBeCloseTo` with an explicit
precision for floating metrics; do not snapshot the entire Color.js object.

Update `palette.test.ts` to assert the exact ordered weight contract for every
generated Scale and literal representative output for at least one Scale. Keep
the existing structural assertions.

**Verify**: `npm run test -- src/engine/__tests__/scale.test.ts src/engine/__tests__/palette.test.ts`
→ all tests pass.

### Step 3: Decouple the CLI test

Delete `buildExpected` and its production `buildScale` dependency from
`cli-scale.test.ts`. Build the expected CLI response from the literal fixture.
The CLI process remains the system under test; expected output must not execute
the same generator in the test process.

**Verify**: `rg "buildExpected|buildScale" src/engine/__tests__/cli-scale.test.ts`
→ no matches, then `npm run test -- src/engine/__tests__/cli-scale.test.ts` →
all tests pass.
